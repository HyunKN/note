# CS329A 강의 요약 및 질문·답변 정리

## 강의 5줄 요약

1. LLM은 먼저 많은 글을 읽는 **사전학습(Pre-training)**을 하고, 이후 사람의 지시를 따르도록 **파인튜닝(Fine-tuning)**된다.
2. 학습이 끝난 뒤에도 답을 여러 개 만들거나 더 오래 생각하게 하면 정답률이 올라갈 수 있는데, 이를 **테스트 시간 스케일링(Test-time scaling)**이라고 한다.
3. 답을 아주 많이 만들면 그중 정답이 포함될 가능성은 커지지만, 진짜 정답을 골라내려면 **검증기(Verifier)**가 필요하다.
4. 검증된 좋은 풀이 과정은 다시 학습 데이터로 사용하여 모델을 개선할 수 있으며, 이런 AI 생성 풀이를 **합성 추론 과정(Synthetic reasoning trace)**이라고 한다.
5. 결국 스스로 발전하는 AI를 만들려면 답을 잘 생성하는 능력뿐 아니라, 답을 정확하고 빠르고 싸게 평가하는 **검증 능력**이 중요하다.

---

## 질문·답변 대화 정리

### 1. 1만 개의 답을 만드는 이유

**나:** 1만 개 중에 답이 몇 개라도 있으면 풀 가능성이 있다는 것이 원숭이 이론의 핵심인가?

**답변:** 맞다. 같은 문제를 아주 많이 풀게 하면 그중 하나쯤 정답이 나올 가능성이 커진다는 뜻이다. 하지만 정답이 섞여 있다는 것과, 그 정답을 실제로 찾아 제출하는 것은 다른 문제다.

```text
답 10,000개 생성
→ 그 안에 정답이 있을 가능성 증가
→ 검증기가 진짜 정답을 찾아야 함
```

---

### 2. 검증기는 사람이 구현해야 하는가?

**나:** 검증기 자체는 따로 사람이 구현해줘야 한다는 것인가?

**답변:** 기본적으로는 사람이 검사 기준을 정해야 한다. 코딩 문제라면 테스트 코드를 만들고, 계산 문제라면 정답 비교 방법을 만든다. 다른 AI를 검증기로 사용할 수도 있지만, 그 AI가 무엇을 좋은 답으로 판단할지는 결국 사람이 기준을 마련해야 한다.

---

### 3. 1만 개를 만들면 너무 느리지 않은가?

**나:** 답을 1만 개 만들면 지연시간이 너무 길어지지 않는가?

**답변:** 한 개씩 차례대로 만들면 오래 걸리지만, 서로 독립적인 답은 여러 GPU에서 동시에 만들 수 있다. 그러면 기다리는 시간은 줄일 수 있지만, 전체 GPU 사용량과 비용은 크게 증가한다.

```text
순차 생성 → 느리지만 장비가 적게 필요함
병렬 생성 → 빠르지만 장비와 비용이 많이 필요함
```

---

### 4. 자동 검증 도구가 없는 문제는 어떻게 하는가?

**나:** 코딩 테스트 같은 검증 도구가 없는 문제에서는 정답을 어떻게 고르는가?

**답변:** 다른 AI가 평가하거나, 여러 답 중 가장 많이 나온 결론을 고르거나, 사람이 일부를 평가할 수 있다. 하지만 글쓰기나 사업 전략처럼 정답이 하나가 아닌 문제는 완벽한 자동 채점이 어려워서 성능 향상이 제한된다.

---

### 5. 온도(Temperature)는 모델 튜닝인가?

**나:** 온도 이야기는 모델 튜닝 같은 것인가?

**답변:** 아니다. 온도는 모델을 다시 학습시키는 값이 아니라, 답을 만들 때 얼마나 다양하게 뽑을지를 조절하는 값이다.

```text
낮은 온도 → 비슷하고 안정적인 답
높은 온도 → 다양하지만 엉뚱한 답도 증가
```

답을 1만 개 만들 때 온도가 너무 낮으면 같은 답만 반복되므로, 적당히 다양하게 만들기 위해 온도를 조절한다.

---

### 6. Pre-training → Fine-tuning → Test-time → Fine-tuning 그림

**나:** 이 순환 그림은 무슨 뜻인가?

**답변:** 테스트 시간에 여러 풀이를 만들고, 검증기로 좋은 풀이를 고른 뒤, 그 풀이를 다시 학습 자료로 사용한다는 뜻이다.

```text
여러 풀이 생성
→ 좋은 풀이 선택
→ 학습 자료로 저장
→ 다시 Fine-tuning
→ 더 잘 푸는 모델 생성
```

AI가 만든 좋은 풀이 과정을 **합성 추론 과정**이라고 부른다.

---

### 7. 이것이 역전파인가?

**나:** 다시 파인튜닝으로 돌아가는 것이 역전파 같은 것인가?

**답변:** 전체 순환 과정 자체가 역전파는 아니다. 좋은 풀이를 학습 데이터로 다시 넣는 과정이고, 실제 파인튜닝을 할 때 모델의 가중치를 고치는 방법으로 역전파가 사용된다.

```text
좋은 풀이 선택 = 공부할 교재를 만드는 일
역전파 = 그 교재를 보고 모델의 머릿속 숫자를 고치는 방법
```

---

### 8. 잘 푼 답인지는 어떻게 아는가?

**나:** 어떤 풀이가 잘 푼 답인지 어떻게 아는가?

**답변:** 검증기가 채점한다. 계산 문제는 정답과 비교하고, 코드는 테스트를 실행한다. 정답이 하나가 아닌 문제는 사람이나 다른 AI가 정확성, 논리성, 조건 충족 여부 등을 평가한다.

---

### 9. 테스트 시간 스케일링이란 무엇인가?

**나:** 테스트 시간에 스케일링이 발생한다는 것은 무슨 뜻인가?

**답변:** 모델의 크기가 커진다는 뜻이 아니다. 학습이 끝난 같은 모델에게 실제 문제를 풀 때 더 많은 계산과 생각할 기회를 주면 성능이 올라간다는 뜻이다.

```text
빠르게 한 번 답하기
vs
여러 풀이 시도 → 검토 → 수정 → 최종 답 선택
```

파라미터는 그대로지만 답을 만들 때 사용하는 계산량이 늘어난다.

---

### 10. 왼쪽과 오른쪽 그래프는 Training 정확도와 Test 정확도인가?

**나:** 왼쪽은 트레이닝 정확도, 오른쪽은 테스트 정확도를 보여주는 것 아닌가?

**답변:** 아니다. 두 그래프 모두 AIME 수학시험 정확도를 측정한다. 차이는 가로축에서 무엇을 늘렸는가이다.

- **왼쪽:** 학습할 때 사용한 계산량을 늘렸을 때 AIME 정확도가 어떻게 변하는지 보여준다.
- **오른쪽:** 학습이 끝난 모델이 답을 만들 때 사용하는 계산량을 늘렸을 때 AIME 정확도가 어떻게 변하는지 보여준다.

`AIME accuracy during training`은 **훈련 데이터 정확도**라는 뜻이 아니라, **훈련을 진행하는 동안 중간중간 AIME로 평가한 정확도**라는 뜻이다.

```text
왼쪽: 공부를 더 시키면 시험 성적이 오른다.
오른쪽: 같은 학생에게 더 오래 생각하게 해도 시험 성적이 오른다.
```

---

### 11. Training / Validation / Test 데이터 분할과 같은 이야기인가?

**나:** Training → Validation → Test로 최종 정확도를 확인하는 일반적인 과정과 같은 것인가?

**답변:** 아니다. 일반적인 데이터 분할은 어떤 데이터를 공부와 평가에 사용할지 나누는 과정이다. 이 강의의 그래프는 데이터 분할을 비교하는 것이 아니라, **학습 계산량**과 **추론 계산량**이 성능에 주는 영향을 각각 비교한다.

---

### 12. 검증이 왜 병목인가?

**나:** 검증이 왜 병목인가?

**답변:** 답을 많이 만드는 것은 비교적 쉽지만, 그중 진짜 좋은 답을 빠르고 정확하게 고르는 것은 어렵기 때문이다.

```text
답 10,000개 생성
→ 최대 10,000개를 검사해야 함
→ 검증기가 틀리면 오답을 정답으로 선택할 수 있음
```

특히 정답이 하나로 정해지지 않은 문제는 채점 기준을 만들기 어렵다. 잘못된 답을 좋은 답으로 선택해 다시 학습시키면 모델이 오답을 배울 수도 있다. 따라서 검증기는 정확하면서도 빠르고 저렴해야 하는데, 이 세 조건을 모두 만족시키기가 어려워 전체 발전을 막는 병목이 된다.

---

## 전체 흐름 한눈에 보기

```text
사전학습
→ 지시를 따르도록 파인튜닝
→ 실제 문제에서 여러 풀이 생성
→ 검증기로 좋은 풀이 선택
→ 좋은 풀이를 다시 학습 데이터로 사용
→ 모델 개선
→ 같은 과정 반복
```

> 핵심: AI가 스스로 좋아지려면 좋은 답을 만드는 능력과 좋은 답을 알아보는 능력이 함께 필요하다.
