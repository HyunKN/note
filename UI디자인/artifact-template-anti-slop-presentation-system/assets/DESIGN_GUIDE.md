# Anti-Slop Presentation System — Detailed Design & QA Guide

이 문서는 PPT/PDF 발표자료를 만들 때 반복적으로 적용할 **디자인·타이포그래피·정보 구조·시각화·검수 규칙**을 정리한 기준 문서다.
목표는 단순히 “예쁜 슬라이드”가 아니라, 사람이 직접 조사하고 편집한 것처럼 **의도가 명확하고 읽기 쉬우며 근거가 보이는 발표자료**를 만드는 것이다.

---

## 0. 핵심 철학

### 0.1 한 슬라이드 = 한 메시지
- 슬라이드마다 가장 먼저 전달해야 하는 사실/문제/결론을 1개만 정한다.
- 제목은 섹션명이 아니라, 가능한 경우 **그 슬라이드가 말하려는 사실을 직접 설명**한다.
- 본문은 제목을 증명하거나 구체화하는 역할만 한다.

### 0.2 “멋있어 보이는 문장”보다 “바로 이해되는 문장”
금지 예시:
- “공간을 다시 해석한다”
- “맥락을 연결한다”
- “경험을 확장한다”
- “새로운 관점으로 전환한다”
- “정보의 경계를 허문다”

권장:
- “낯선 관광지에서는 현재 위치와 다음 이동 방향을 빠르게 판단하기 어렵다.”
- “여행객은 지도·안내판·검색을 상황에 따라 함께 사용한다.”
- “영문 장소명이 검색되지 않아 한글명을 찾아 다시 검색한 사례가 있었다.”

제목만 읽고도 **누가 / 어떤 상황에서 / 무엇이 어려운지** 이해되어야 한다.

### 0.3 기존 원문보다 더 추상적으로 만들지 않는다
- 문제정의 문장이 이미 명확하면 그대로 쓰거나 더 쉽게 풀어쓴다.
- 한 문장으로 압축하려다 의미를 흐리지 않는다.
- 발표자가 구두로 설명해야만 이해되는 제목은 실패로 본다.

---

# 1. AI Slop 방지 규칙

## 1.1 기본 금지 패턴
특별한 기능적 이유가 없는 한 다음을 사용하지 않는다.

- Side Accent Bar
- Side-Tab Card
- 알약형 pill badge의 반복
- 모든 내용을 둥근 카드에 넣는 card grid
- Glassmorphism / 과한 blur card
- 의미 없는 glow / neon
- 장식용 gradient 남발
- 이모지
- 의미 없는 아이콘 타일
- 반복되는 “3개 카드 + 아이콘 + 짧은 설명” 구성
- 근거 없는 수치 스트립: `500+ / 98% / 24-7` 등
- 너무 큰 숫자를 장식처럼 두고 기준 시점·의미를 설명하지 않는 구성
- 모든 슬라이드에 같은 템플릿을 복제하는 구성
- 텍스트보다 장식 요소가 더 많은 구성
- 낮은 대비의 작은 회색 문장
- 제목·본문·출처가 모두 같은 무게로 경쟁하는 구성
- 한 슬라이드에 4~6개의 작은 정보 박스를 촘촘히 배치
- “혁신”, “미래”, “연결”, “경험”, “맥락” 같은 추상어로 의미를 대신하는 헤드라인

## 1.2 카드 사용 원칙
카드는 금지 요소가 아니라 **필요할 때만 쓰는 UI 컨테이너**다.

카드를 써도 되는 경우:
- 항목 간 독립성이 강함
- 배경과 분리해야 이해가 쉬움
- 선택지/제품/기능처럼 실제 UI적 구분이 중요함

카드를 피해야 하는 경우:
- 단순한 텍스트 목록
- 문제 5개를 같은 중요도로 보이게 만드는 경우
- 표나 정렬만으로 충분한 경우
- 공백과 구분선만으로 충분한 경우

# 2. 컬러 시스템

## 2.1 기본 원칙: 60 : 30 : 10
- **60% Base**: White / very light cool neutral
- **30% Secondary**: Sky blue / light cyan 계열
- **10% Accent**: Lilac / soft pink / selective sky-blue emphasis

정확히 픽셀 면적을 계산하는 규칙이 아니라, **시각적 지배력**을 60/30/10으로 유지한다.

## 2.2 기본 팔레트
### Base
- White: `#FFFFFF`
- Cool Gray 50: `#F6F8FA`
- Cool Gray 100: `#EEF2F5`

### Text
- Primary: `#17191C` 또는 `#1C1F23`
- Secondary: `#5F6772`
- Muted: `#7A838E`
- Divider: `#D9E1E8`

### Main accent
- Sky Blue: `#73C7F2`
- Light Sky: `#A8DFFF`
- Cyan: `#82E0EE`

### Minor accent
- Lilac: `#C8B8FF`
- Soft Pink: `#F2A7D9`

## 2.3 금지 색조
- Deep blue / navy / cobalt를 메인으로 사용하지 않는다.
- 누런 cream / beige off-white를 기본 배경으로 사용하지 않는다.
- 진한 파랑 + 보라 + 핑크를 모두 동시에 강하게 쓰지 않는다.

## 2.4 Gradient 규칙
OpenAI 계열에서 보이는 듯한 **soft, blurred, airy gradient**를 참고하되 그대로 복제하지 않는다.

사용 가능:
- 표지
- 섹션 전환
- 마지막 결론 슬라이드
- 매우 약한 corner wash

사용 금지:
- 모든 본문 슬라이드 전체 배경
- 텍스트 가독성을 낮추는 고채도 gradient
- 네온처럼 선명한 gradient

권장 구성:
- sky blue 중심
- cyan 보조
- 아주 약한 lilac/pink corner accent
- 본문 슬라이드는 white base 유지

# 3. 타이포그래피

## 3.1 글꼴
한글 발표자료는 읽기 쉬운 sans-serif를 우선한다.

권장:
- Noto Sans CJK KR
- Pretendard 계열이 사용 가능하면 사용
- Wanted Sans 계열이 사용 가능하면 사용
- NanumBarunGothic은 fallback

금지/주의:
- Thin/Light를 본문에 사용하지 않음
- 장식체를 핵심 정보에 사용하지 않음
- 여러 폰트 패밀리를 섞지 않음

## 3.2 크기 가이드
16:9 발표 기준 일반 권장치:
- Main headline: 30–38 pt
- Hero headline: 40–50 pt 가능
- Section label: 9–12 pt, uppercase/letter spacing 제한적 사용
- Subheading: 18–24 pt
- Body: 18–22 pt
- Supporting note: 13–16 pt
- Source/citation: 9–11 pt

본문을 억지로 14pt 이하로 줄여 넣지 않는다.
정보가 많으면 슬라이드를 분리한다.

## 3.3 한국어 우선
한국어 발표에서 영어는 보조 정보다.

실제 영문 후기 인용 예:

**안내 표지가 매우 적다**

`원문: “signage is minimal”`

- 한국어 의미를 먼저 크게 보여준다.
- 영문 원문은 바로 아래 작고 회색으로 둔다.
- 영문만 크게 두고 청중이 해석하도록 방치하지 않는다.

## 3.4 영어 라벨 병기
필요하면 다음처럼 쓴다.
- 불편 `PAIN`
- 원하는 점 `GAIN`
- 현재 위치 `WHERE`

영문은 정보 계층상 보조이므로 한국어보다 크거나 강하게 만들지 않는다.

# 4. 헤드라인 작성

## 4.1 제목은 직접적인 문장
좋은 제목은 별도 해석이 필요 없다.

나쁨:
> 관광객은 위치를 찾은 뒤에도 공간을 다시 해석한다

좋음:
> 낯선 관광지에서는 현재 위치와 다음 이동 방향을 빠르게 판단하기 어렵다

## 4.2 불필요한 마케팅 카피 금지
- “새로운 경험의 시작”
- “여행의 미래를 다시 쓰다”
- “공간을 이해하는 새로운 방식”

같은 표현은 실제 자료가 그 주장을 요구하지 않는 한 쓰지 않는다.

## 4.3 줄바꿈
수동 줄바꿈은 문법 단위에서 한다.

좋음:
> 낯선 관광지에서는 현재 위치와
> 다음 이동 방향을 빠르게 판단하기 어렵다

피함:
> 지도에서 위치는 보여도,
> 눈앞의 장소와 갈 방향은…

주의:
- 첫 줄 끝에 쉼표를 남기지 않는다.
- 조사/어미를 다음 줄에 혼자 보내지 않는다.
- 괄호 시작/끝이 줄 경계에서 어색하지 않은지 본다.
- 한글 기준 실제 렌더 폭을 확인한다.

---

# 5. 그리드와 좌우 배치

## 5.1 기본
- 좌측 정렬을 기본으로 한다.
- 페이지마다 주요 시작선을 고정한다.
- 제목, 본문, 차트의 왼쪽 시작선을 가능한 한 맞춘다.
- 완전 대칭보다 내용이 요구하는 비대칭을 우선한다.

## 5.2 동일 폭 칼럼
`WHERE / WHAT / CONTEXT / DIRECTION`처럼 길이가 다른 항목을 한 줄에 놓을 때:
- 텍스트 사이에 `+` 문자를 수동 배치하지 않는다.
- 동일 폭 칼럼 또는 grid를 만든다.
- 각 칼럼 안에서 제목/값을 정렬한다.
- 구분선, 점, connector는 shape로 만든다.

## 5.3 Collision-safe layout
PowerPoint 좌표가 겹치지 않아도 렌더링 결과에서는 글꼴 폭 때문에 겹칠 수 있다.

반드시:
1. PPTX 생성
2. PDF 변환
3. PNG 렌더
4. 실제 글자 bounding area를 눈으로 확인
5. 겹치거나 너무 가까우면 재조정

특히 주의:
- 긴 한글 제목
- 영어+한글 혼용
- `설명 · 주변 POI`처럼 폭이 긴 짧은 문구
- 쉼표/따옴표가 끝에 붙는 제목
- 2줄에서 3줄로 변하는 본문

# 6. Vertical Rhythm — 위아래 간격

좌우 정렬만큼 **수직 간격**이 중요하다.

권장 시작점:
- 섹션 라벨 → 메인 제목: 0.25–0.35 in
- 메인 제목 → 첫 콘텐츠: 0.30–0.45 in
- 소제목 → 본문/값: 0.18–0.28 in
- 정보 블록 → 다음 블록: 0.45–0.70 in
- 콘텐츠 마지막 줄 → 출처: 최소 0.30 in
- 푸터 텍스트 → 구분선: 0.08–0.15 in 이상의 명확한 간격

## 6.1 텍스트박스 높이를 믿지 않는다
PowerPoint 텍스트박스의 박스 높이보다 **실제로 보이는 마지막 글자 줄**을 기준으로 다음 요소를 배치한다.

## 6.2 2줄 제목
2줄 제목 아래 콘텐츠는 1줄 제목과 같은 y 좌표에 놓지 않는다.
실제 제목 높이만큼 내려야 한다.

---

# 7. Footer / Divider Safe Zone

## 7.1 하단 안전영역
슬라이드 하단 약 0.55–0.70 in은 출처, 발표 정보, 페이지 번호용 영역으로 남긴다.
주요 본문/그래픽이 내려오지 않게 한다.

## 7.2 선과 글자 겹침 금지
구분선과 푸터 텍스트는 별도 y 위치를 가진다.

나쁨:
- 푸터 글자 중앙을 선이 관통
- baseline과 divider가 붙어 하나의 취소선처럼 보임

좋음:
- 본문
- 충분한 공백
- divider
- 별도 푸터 텍스트
- 페이지 번호

또는
- 푸터 텍스트
- 충분한 공백
- divider

둘 중 하나로 일관되게 설계한다.

## 7.3 전체 페이지 하단 크롭 검수
최종 렌더 후 모든 페이지의 하단 10~15%만 모은 contact sheet를 만들어 비교한다.
- line/text overlap
- page number 위치
- source line 높이
- footer baseline
을 한 번에 확인한다.

# 8. 숫자와 데이터 시각화

## 8.1 숫자만 크게 쓰지 않는다
`71.1%`가 핵심이면 실제 비율을 한눈에 이해하도록 시각화한다.

예:
- 0–100 비례 막대
- 전후 비교: 100 → 116.4
- 작은 slope/bar comparison

## 8.2 숫자 옆 필수 정보
항상 함께 적는다.
- 무엇의 수치인지
- 기준 연도/기간
- 출처

## 8.3 fake metric strip 금지
근거 없는 `500+`, `98%`, `24/7` 같은 장식용 숫자를 만들지 않는다.

## 8.4 차트는 데이터 종류에 맞게
- 비율 비교 → bar
- 시계열 → line
- 전후 비교 → paired bar / slope
- 여러 단계의 사용자 행동 → flow/process
- 사례 비교 → editorial columns / rows

# 9. 콘텐츠 유형별 레이아웃 변형

같은 카드 레이아웃을 반복하지 않는다.

## 9.1 Cover
- 큰 제목 1개
- 필요한 최소 정보만
- soft sky/cyan/lilac gradient 사용 가능
- 장식보다 제목이 먼저 보여야 함

## 9.2 Research / Data
- 핵심 숫자 + 실제 비례 시각화
- 옆에 1~2문장 해석
- 출처는 숫자와 가까운 하단

## 9.3 AS-IS / Journey
- 단계 → 사용 수단 → friction을 구조적으로 보여준다.
- 화살표는 텍스트 `→`보다 실제 connector line/arrow shape를 선호한다.
- 모든 단계의 텍스트 높이를 맞춘다.

## 9.4 Problem Definition
- 가장 중요한 1~2개를 크게
- 보조 문제는 작게
- 문제 5개를 모두 같은 카드로 만들지 않는다.

## 9.5 User Review / Evidence
Editorial layout을 사용한다.
예:
- 장소/출처
- 한국어 핵심 의미
- 작은 영문 원문
- 이 사례가 보여주는 점

불편 사례만 모으지 말고 긍정 반례도 분리해 보여준다.

## 9.6 Persona / Empathy
텍스트만 빽빽하게 두지 않는다.
가능하면:
- 여행 상황 이미지
- 맵/스마트폰/현장 탐색 이미지
- 조사에서 나온 대표 행동 흐름
을 함께 사용한다.

주의:
- 합성 페르소나를 실제 인터뷰 대상처럼 보이게 하지 않는다.
- 이미지가 실제 조사 참여자 사진인 것처럼 오해되지 않게 한다.
- `실제 관광객 후기·조사자료를 종합한 가상 페르소나`라고 명시한다.

## 9.7 Existing Solutions
카드보다 row comparison을 우선한다.

예:
| 기존 수단 | 잘하는 것 | 남는 문제 |

기존 서비스가 잘하는 점을 먼저 인정한다.
“기존 지도는 부족하다” 같은 과장된 framing을 피한다.

## 9.8 Conclusion
- 정보량을 줄인다.
- 핵심 방향 1개만 크게 남긴다.
- 필요하면 soft gradient 사용
- 결론은 추상 카피가 아니라 실제 프로젝트 방향을 직접 쓴다.

# 10. 이미지 사용

## 10.1 이미지는 장식이 아니라 설명
사용 이유가 분명해야 한다.
- Persona → 실제 여행 상황의 맥락
- 조사 사례 → 장소/지도/후기 시각 증거
- 제품 → 실제 화면
- 공간 문제 → 지도/현장 관계

## 10.2 Persona 이미지
사용자가 실제 특정 인물을 조사한 것이 아니라면:
- 일반 여행 상황 이미지 또는 illustration
- “대표 사용자 맥락” 이미지
를 사용한다.

가짜 인터뷰 사진처럼 보이는 연출은 피한다.

## 10.3 이미지가 없을 때
의미 없는 stock photo보다:
- 간단한 route diagram
- 실제 데이터 chart
- 실제 review snippet
- map crop
을 우선한다.

# 11. 리뷰/인용 처리

## 11.1 번역 우선순위
한국 청중:
1. 한국어 의미 — 크게
2. 원문 — 작게
3. 출처 — 더 작게

## 11.2 직접 인용과 요약을 구분
따옴표는 실제 원문에만 사용한다.
재구성한 문장은:
- “후기에서 반복된 행동을 요약”
- “여러 사례를 종합한 표현”
이라고 명시한다.

# 12. 출처와 근거

- 중요한 수치는 같은 슬라이드에서 출처를 확인할 수 있게 한다.
- 모든 출처를 마지막 페이지에만 몰아넣지 않는다.
- 정부·기관 자료와 기업 자체 자료는 성격을 구분한다.
- 한 사용자 후기 = 사례이며 전체 사용자 통계가 아니다.
- 긍정 사례와 부정 사례를 함께 고려한다.

# 13. PDF/PPT 출력 규칙

## 13.1 PPTX는 작업 원본
- editable text/shape 유지
- 가능하면 arrow와 separator를 shape로 생성
- 텍스트 glyph 화살표는 최소화

## 13.2 PDF는 최종 시각 QA 기준
PowerPoint 내부 화면만 보고 완료하지 않는다.
PDF 렌더가 실제 발표/제출 품질의 기준이다.

## 13.3 최종 렌더 절차
1. PPTX 생성
2. PDF 변환
3. PDF 전체 페이지 PNG 렌더
4. montage 생성
5. 필요한 페이지 확대 확인
6. 하단 contact sheet 확인
7. 수정
8. 다시 렌더

# 14. 최종 QA 체크리스트

## 14.1 Content
- [ ] 슬라이드 제목만 읽어도 흐름이 이해되는가?
- [ ] 제목이 원문 문제정의보다 추상적이지 않은가?
- [ ] 멋있어 보이기 위한 문장이 없는가?
- [ ] 근거 없는 숫자가 없는가?
- [ ] 실제 후기와 해석을 구분했는가?
- [ ] 긍정 반례가 필요한 경우 포함했는가?

## 14.2 AI Slop
- [ ] Side Accent Bar가 없는가?
- [ ] Side-Tab Card가 없는가?
- [ ] pill badge가 반복되지 않는가?
- [ ] 카드 grid가 불필요하게 반복되지 않는가?
- [ ] 이모지가 없는가?
- [ ] 의미 없는 아이콘이 없는가?
- [ ] 장식용 metric strip이 없는가?
- [ ] glass/glow/gradient가 과하지 않은가?
- [ ] 동일 레이아웃을 연속해서 복제하지 않았는가?

## 14.3 Typography
- [ ] 본문이 발표 환경에서 읽히는 크기인가?
- [ ] 한국어가 먼저 읽히는가?
- [ ] 영어는 보조 정보로 계층이 낮은가?
- [ ] 제목 줄바꿈이 문법적으로 자연스러운가?
- [ ] 쉼표가 줄 끝에 어색하게 남지 않았는가?
- [ ] 조사/어미가 혼자 다음 줄로 떨어지지 않았는가?

## 14.4 Spacing
- [ ] 제목과 첫 콘텐츠 사이에 충분한 간격이 있는가?
- [ ] 라벨과 값은 하나의 그룹으로 보이는가?
- [ ] 서로 다른 정보 블록 사이 간격이 더 큰가?
- [ ] 이미지와 캡션이 너무 멀지 않은가?
- [ ] 출처와 본문이 붙지 않았는가?

## 14.5 Collision
- [ ] 텍스트끼리 겹치지 않는가?
- [ ] 선과 텍스트가 겹치지 않는가?
- [ ] divider가 취소선처럼 보이지 않는가?
- [ ] footer와 본문이 겹치지 않는가?
- [ ] page number가 다른 요소와 충돌하지 않는가?

## 14.6 Color
- [ ] 60/30/10 시각 비율이 유지되는가?
- [ ] deep blue/navy를 메인으로 쓰지 않았는가?
- [ ] cream/yellowish off-white 배경을 쓰지 않았는가?
- [ ] sky blue가 주 강조색인가?
- [ ] lilac/pink는 10% 이내의 보조 accent인가?
- [ ] gradient가 표지/전환/결론 위주로 제한됐는가?

## 14.7 Data
- [ ] 숫자에 시각적 스케일이 있는가?
- [ ] 수치의 기준 시점이 적혀 있는가?
- [ ] 데이터 시각화가 사실을 왜곡하지 않는가?

## 14.8 Render
- [ ] 모든 슬라이드를 PNG로 확인했는가?
- [ ] montage에서 밀도와 흐름을 확인했는가?
- [ ] 문제 페이지를 확대 확인했는가?
- [ ] 하단 contact sheet로 푸터/선 겹침을 확인했는가?

# 15. 상황별 판단 우선순위

디자인 규칙이 충돌할 때 우선순위:

1. **내용 정확성**
2. **즉시 이해 가능성**
3. **가독성**
4. **정보 계층**
5. **정렬/간격**
6. **시각적 아름다움**
7. **트렌디함**

즉 “예쁜데 무슨 말인지 모르겠다”면 실패다.

# 18. 유지보수 원칙

사용자가 새로운 디자인 피드백을 줄 때는 다음을 한다.
1. 피드백을 특정 슬라이드 수정으로만 끝내지 않는다.
2. 반복 가능한 일반 규칙으로 추상화한다.
3. 이 가이드에 규칙을 추가한다.
4. 기존 규칙과 충돌하면 더 최근의 명시적 사용자 지시를 우선한다.
5. 최종 참고 PPTX도 최신 규칙을 반영한 버전으로 교체한다.

현재 기준 reference visual은 **sky-blue / soft cyan-lilac gradient / white content slides / Korean-first / evidence-first / editorial layout / render-first QA** 방향이다.
